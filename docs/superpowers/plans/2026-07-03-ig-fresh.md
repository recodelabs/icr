# ig-fresh Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A standalone CLI (`ig-fresh build -i <publisher-output> -o <site>`) that regenerates an HL7 IG Publisher output directory as a modern, searchable static site, proven on the ICR IG.

**Architecture:** Load publisher-emitted JSON (ImplementationGuide resource, artifact resources with computed snapshots, expansions.json) plus narrative extracted from generated HTML → normalize into a typed model → render static pages with build-time Preact JSX (no client React), Tailwind v4 CSS with shadcn-style tokens, small vanilla-JS islands, fuse.js command palette + Pagefind full-text search. Page filenames match the publisher's so all links keep working; unrendered publisher files are copied through.

**Tech Stack:** Node ≥20, TypeScript (ESM), preact + preact-render-to-string, cheerio, shiki, fuse.js (client), pagefind, tailwindcss v4 CLI, vitest.

## Global Constraints

- Spec: `docs/superpowers/specs/2026-07-03-ig-fresh-design.md` (icr repo). Fidelity contract: same page filenames, same page tree/menu, artifact set, canonicals, status banner; copy through what we don't re-render (`qa.html`, `.json/.xml/.ttl` renditions, `package.tgz`, images).
- ig-fresh repo: `~/github/ig-fresh` (new git repo). Working example input: `~/github/icr/ig/output`.
- One bad artifact never fails the build: log a warning, emit the generic fallback page.
- No client-side framework runtime; interactivity is hand-written vanilla JS islands.
- All client assets self-contained in the site dir (works from `file://` except where a viewer needs http — document `npx serve`).

### Task 5: Element tree builder (the core of profile pages)

**Files:**
- Create: `src/model/element-tree.ts`
- Test: `test/element-tree.test.ts` (fixture: trimmed snapshot with nested elements, a slice, a choice type, a binding)

**Interfaces:**
- Produces:

```ts
export interface ElementNode { path: string; sliceName?: string; label: string; /* last path segment or slice */
  min: number; max: string; short?: string; definition?: string;
  types: {code: string; profiles?: string[]; targetProfiles?: string[]}[];
  mustSupport: boolean; isModifier: boolean; isSummary: boolean;
  binding?: {strength: string; valueSet?: string};
  fixed?: string; /* rendered fixed/pattern value if present */
  inDifferential: boolean; children: ElementNode[]; }
export function buildElementTree(sd: any): {differentialIds: Set<string>; root: ElementNode};
```

- Algorithm: iterate `snapshot.element`; skip the root element as tree root container; parent = longest previous element whose `id` + "." prefixes this `id` (use element `id`, not `path`, so slices nest correctly under their sliced element). `inDifferential` = element id present in `differential.element`. Choice elements keep `[x]` in label and list all types.
