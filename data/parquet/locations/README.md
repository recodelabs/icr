# ICR location registry

Every Location in the Integrated Campaign Registry (ICR) FHIR server, flattened
to one GeoParquet row per resource: administrative boundaries (country, states,
LGAs — polygons), health facilities and settlements (points), with the
administrative hierarchy denormalised onto each row (admin0…admin4 names and
codes, `path`, `ancestor_ids`) and the complete FHIR resource kept in
`fhir_json`. Nigeria is complete (812 admin units, 51,022 facilities, 292,438
settlements, from GRID3 and the NHFR via the ICR); Sierra Leone holds a
handful of test records so far.

Hive-partitioned by `country` / `geom_type` / `type`, one zstd-compressed file
per partition, 20,000-row groups in Hilbert order with a `bbox` covering column
and native Parquet GEOMETRY statistics, so a reader can fetch only the row
groups it needs over HTTP range requests. Geometry is WGS 84 (OGC:CRS84) WKB.

## Processing Notes

Exported from the ICR FHIR server (HL7 FHIR R4 Location resources, profiled by
the ICR Implementation Guide) with kiln (https://github.com/recodelabs/kiln):
incremental `_lastUpdated` extract to an NDJSON snapshot, then a transform that
resolves the `partOf` hierarchy, converts positions and boundary extensions to
WKB, and writes the partitioned GeoParquet. FHIR stays the master; this table is
a derived projection and is regenerated in full on each refresh
(tools/warehouse/refresh.sh in the ICR repo). The collection datetime is the
time of that snapshot.

## Known Issues

1,653 Nigerian points fall outside the polygon of their `partOf` admin unit
(source data quality; listed in parquet/_report.json). 3 facilities have no
usable geometry and are dropped. `type=null` holds Locations without a type
code. Sierra Leone is test data, not a registry. The PMTiles (rel="pmtiles"
links) cover Nigeria only and are rebuilt separately from the parquet
(tools/warehouse/tiles.sh), so they can lag a refresh. No thumbnail yet.
